Google's OpenAI API compatible endpoint and package is used over the genai library for better future compatibility.
MarkItDown was chosen and used initially but because of the two-column structure of the tariff PDFs, it was discovered that MarkItDown wasn't the best option, so other libraries were used for this purpose and MarkItDown is kept for other file types (Although it got the [pdf] extension along with it). So it can be discarded from the project.
Usually "ruff" is used for Python code reformatting, but Pycharm's "Ctrl+Alt+L" was prefered instead.
The goal was to follow the KISS principle so LangChain, Mlflow, Docker were not used at first; LangChain and Docker were added to the project later on for scalability and maintainability.
Many other LLM API providers were leveraged during development, but most of them were not responding or had limitations (e.g. Groq free API has 8K context limit per minutes). Google's Gemini API also responded with "Model under high demand" most of the time, this was a challenge during development, but Gemini was the most suitable option in the end, as mentioned in the assignment document too.
Before implementing the RAG pipeline, putting the whole document into the model's context was tried, and it was sunshine and rainbow in terms of performance and accuracy, but obviously not efficient at all in terms of cost and token usage, and far from the goal of the project, but good as a baseline to begin with.
For embedding generation, HF TEI is used. This is because handling memory has always been a challenge in previous projects, so this is the best known option personally, because it completely handles the embedding related stuff so that we can use it as easy as calling an endpoint from the application's POV. Embedding currently happens on the CPU (CPU variant of TEI is used), slow, but it would be more compatible and easier to run. The embedding model is BGE-M3 which is a perfect known option for multi-lingual projects. Probably not required for this project but it has other benefits too, for example it has internal capability for learned sparse embedding generation which can be beneficial in most RAG pipelines (Hybrid search in RAG).
Git is used for version control during development.
